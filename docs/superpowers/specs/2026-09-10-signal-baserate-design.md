**日期**：2026-09-10
**狀態**：已與使用者確認，待實作計畫
**前置文件**：`2026-08-31-stock-forecast-design.md`（以下稱「原 spec」）

## 0. 這份規格書存在的理由

2026-08-31 留存了 88 筆預測。2026-09-10 回頭比對（`run.py --accuracy`，
期間走了 7~8 個交易日，目標期間 20 日，尚未走滿）：

| | 方向命中率 | IC 秩相關 | 多空價差 |
|---|---|---|---|
| 台股 (54) | 53.7% (p=0.68) | +0.014 (p=0.92) | −1.43% |
| 美股 (34) | 41.2% (p=0.39) | −0.150 (p=0.40) | +0.08% |
| **全體 (88)** | **48.9% (p=0.92)** | **−0.019 (p=0.86)** | **−0.73%** |

**目前沒有任何證據顯示模型有預測力。** 必須同時講公平的部分：
n=88、期間只走了三分之一、無一筆到期，這個樣本量在兩個方向上都
證明不了什麼。所以正確的敘述是「沒有證據證明有效」，不是「已證明無效」。

但另有一件不需要統計就能斷定的事。查 `predictions` 表中預測漲幅
與信心度的關係，得到完全反向的單調結構：

| 信心度 | 筆數 | 漲幅中位數 | 最大漲幅 |
|---|---|---|---|
| 40–49 | 64 | +2.1% | **+41.0%** |
| 50–59 | 18 | −0.7% | +0.6% |
| 60–69 | 6 | −2.4% | −0.9% |

預測漲幅前 12 名，信心度**全部都是 40**；信心度 > 50 的預測沒有一筆
漲幅超過 +0.6%。

機制在 `compose.py:316-321`：三軌方向分歧時信心度被壓到
`CONFLICT_CONFIDENCE_CAP = 40.0`，而 `MIN_CONFIDENCE_TO_SHOW = 40.0`
—— **兩個常數相等**，所以「三軌吵架」與「剛好可以顯示」是同一個數字。
而巨大的合成漲幅正好只在三軌吵架時出現（某一軌把合成值拉飛）。

結論：`upside_pct` 排序不是報酬預測器，**它是一個分歧偵測器**。
任何以它排序的「買點」功能，都會由結構保證只從最不可信的那一格挑股票。

這份規格書的目的，是讓「一個數字有沒有實證支撐」變成**出貨前的閘門**，
而不是出貨後花 88 筆預測與 10 天才發現的事。

## 1. 目標與非目標

### 1.1 目標

1. 具名訊號取代預測漲幅，成為「值得注意」的唯一依據
2. 每個訊號都必須帶一個實測的歷史基準率，否則不得出貨
3. 修復第 0 節查出的三個缺陷
4. 依使用者自訂規則計算資金配置的**後果**（純算術）
5. 每日產出可貼入外部工具的精簡日報

### 1.2 非目標（明確不做）

- **不提供投資建議。** 不建議買賣、不建議配置比例、不挑選標的。
  資金計算機是算術工具：使用者設定規則，程式計算後果。
- **不宣稱目標價。** 第一階段交付的是波動區間（描述性），不是方向性預測。
  等某個訊號的統計優勢站得住，才有資格從它推導目標價。
- **不搜參數。** 訊號參數用慣例值寫死，不對著結果最佳化（見 §3.4）。
- **不做投資組合最佳化。** 回撤容忍值是檢查項，不是最佳化目標。

### 1.3 資料可得性裁決（決定第一階段範圍）

使用者選定四類訊號家族。查證資料庫後：

| 家族 | 算勝率需要 | 實際擁有 | 第一階段 |
|---|---|---|---|
| 技術面突破與回檔 | 價格序列 | 3 年 × 102 檔＝76,030 bars | **完整交付（含基準率）** |
| 籌碼異動 | 法人／融資／集保序列 | 各 **1 個日期** | 不可用（連「異動」都定義不出） |
| 基本面轉折 | 季報序列 | 2 個 asof，同一季 | 不可用 |
| 事件驅動 | 有日期且無倖存偏誤的新聞史 | 名目 11 個月，69% 集中在最近 1 個月；`sentiment` 9,340 筆全 NULL | 僅顯示新聞，不出訊號 |

「異動」與「轉折」在數學上需要至少兩個時間點；一個快照連變化量都算不出來。

新聞的問題更隱蔽：名目跨 2025-10 ~ 2026-08，但 2025-10 只有 2 則、
2026-08 有 6,477 則。那不是歷史，是 Google News RSS 只回傳近期資料的殘影
—— 留在索引裡的舊新聞，正好是後來被證明重要的那些。拿它回測會系統性
偏向「事後看很準」，屬最嚴重的一類前視偏誤。

**可回補 vs 不可回補**（決定第二階段是抓取工作還是只能等）：

- 可回補：三大法人（TWSE T86／TPEX，每日）、融資融券（MI_MARGN，每日）、
  集保股權分散（TDCC，每週）、季報（3 年＝12 點，天生稀薄）
- 不可回補，只能往前累積：新聞（RSS 結構性只給近期）、
  分析師目標價（Yahoo 僅當前快照）

## 2. 核心物件：訊號與基準率

### 2.1 Signal

```python
# src/signals/base.py
@dataclass(frozen=True)
class Signal:
    key: str                  # "breakout_20d_vol2"
    name: str                 # "20 日新高 + 量增 2 倍"
    family: str               # technical / flow / fundamental / event
    markets: tuple[str, ...]  # 適用市場（籌碼類僅 TW）
    def fires(self, df: pd.DataFrame) -> pd.Series: ...  # bool, index=date
```

`fires` 是純函數，輸入 `features.add_indicators()` 的輸出，
輸出每根 bar 是否觸發。

**純函數是刻意的：它讓「今天掃描」與「三年回測」執行同一段程式。**
這是防前視偏誤最有效的單一措施 —— 掃描與回測若是兩份程式，
它們遲早不一致，而不一致的方向永遠是回測看起來比較準。

Registry 在 `src/signals/__init__.py` 匯出 `REGISTRY: tuple[Signal, ...]`。
新增一個訊號＝一個檔案＋一行註冊。

### 2.2 第一階段訊號清單（技術面，10 個）

全部可由現有 `FEATURE_COLUMNS` 計算：

| key | 規則 |
|---|---|
| `breakout_20d_vol2` | 20 日新高 且 量 ≥ 20 日均量 × 2 |
| `breakout_52w` | 突破 52 週高點 |
| `pullback_ma20_uptrend` | 多頭排列中回測 MA20 未破 |
| `oversold_rsi30_uptrend` | MA20 > MA60 且 RSI14 < 30 |
| `macd_golden_above_zero` | MACD 金叉且在零軸之上 |
| `kd_golden_oversold` | KD 於 20 以下金叉 |
| `bb_squeeze_breakout` | 布林通道收窄後向上突破 |
| `ma_stack_turn` | `bullish_stack` 由 0 轉 1 |
| `volume_dryup_reversal` | 量縮至均量 0.5 倍後放量上漲 |
| `near_high_strength` | 距 52 週高 < 5% 且 `pos_52w` > 0.9 |

### 2.3 BaseRate

```python
@dataclass(frozen=True)
class BaseRate:
    signal_key: str; market: str; horizon: int
    n_fires: int              # 名目觸發次數
    n_effective: float        # 有效獨立樣本
    hit_rate: float           # 前瞻超額報酬 > 0 的比例
    baseline_hit_rate: float  # 同市場「未觸發」bar 的比例（關鍵對照）
    median_excess: float
    ci_low: float; ci_high: float   # block bootstrap
    p_value: float; p_adjusted: float
    verdict: str              # "edge" | "no_edge" | "insufficient"
```

### 2.4 verdict 判定門檻（明確寫死，不留解釋空間）

依序判定，先命中者為準：

1. `insufficient` — `n_effective < 20`
   （20 是刻意保守的下限。有效樣本低於此，任何勝率都是噪音。）
2. `edge` — 同時滿足三個條件：
   - `p_adjusted < 0.10`（BH 校正後，見 §3.3）
   - `ci_low > 0`（bootstrap 信賴區間下界為正）
   - `hit_rate > baseline_hit_rate`（勝過同市場無條件基準，見 §3.5）
3. `no_edge` — 其餘全部

三條件並列的理由：單看 p 值會讓極小但顯著的效果過關；單看 CI 會漏掉
多重檢定；單看勝率會被多頭段的無條件基準騙過。三個各擋一種失敗。

### 2.5 閘門規則（強制）

- 僅 `verdict == "edge"` 得進入「值得注意的買點」
- `no_edge` 照樣顯示今天觸發了什麼，但強制標「無統計優勢」
- `insufficient` 標「樣本不足」
- **沒有 BaseRate 的訊號不得出貨。以 `assert` 實作，不是慣例。**

## 3. 基準率引擎（`src/baserate.py`）

四個會讓勝率變成謊言的陷阱，逐一處置。

### 3.1 前視偏誤

bar `t` 的訊號僅得使用 `≤ t` 的列。前瞻報酬自 `t` 收盤至 `t+N` 收盤，
減同市場基準同期報酬（沿用 `accuracy.py` 既有的超額定義與
`config.TW_BENCHMARK` / `US_BENCHMARK`）。以測試強制，不靠自律（§8.2）。

### 3.2 重疊窗口與橫斷面相關（最致命）

3 年＝736 根 bar。20 日前瞻窗口使連續兩次觸發共用 19/20 的結果；
61 檔台股又同漲同跌。名目 n=3,000 的有效樣本可能只有 40。這正是
第 0 節那 88 筆變成 48.9% 的同一個陷阱。

處置：

- **按日期做 block bootstrap** 求信賴區間。整個日期一起重抽（同一天所有
  標的一起動），block 長度 ≥ horizon。
- `n_effective` 定義為「訊號觸發過的、互不重疊的日期區塊數」，
  **不是觸發次數**。此定義會讓多數訊號的樣本數看起來少得刺眼；
  這是刻意的。

### 3.3 多重檢定

第一階段檢定數＝10 訊號 × 2 市場 × 3 期間（5/10/20 日）＝ **60 次**。
全 registry 做 Benjamini-Hochberg 校正，**原始 p 與校正後 p 並列顯示**，
讓「這個優勢有多少是搜出來的」看得見。看三個期間的代價就在這裡，
必須明示。

### 3.4 參數不得對著結果調

若拿全歷史比較「20 日新高」與「30 日新高」再回報贏家的勝率，
那個勝率是膨脹的。**第一階段完全不搜參數**：每個訊號以慣例參數
寫死一次，絕不對著結果最佳化。這是最省事也最誠實的處置。

### 3.5 基準對照是必需項

「命中率 55%」僅在無條件命中率為 50% 時才有意義。多頭段的無條件
命中率可能是 58%，此時 55% 是負面資訊。故 `baseline_hit_rate` 與
`hit_rate` 一律並列，不得單獨呈現後者。

### 3.6 儲存與執行

新表 `signal_stats`（signal_key, market, horizon, computed_at, 及
BaseRate 全部欄位）。以 `run.py --baserates` 手動重算（需走全歷史，慢），
不在每日流程中。

## 4. 修復既有缺陷

### 4.1 分歧時直接不可預測

`compose.py:43,46` 兩個常數相等是第 0 節那個結構性缺陷的成因。

修法**不是**把 40 改成 35，而是三軌方向分歧時直接 `predictable = False`，
移入「數據觀察」區。理由：方向分歧代表我們沒有觀點，硬給一個合成
中位數是杜撰。且「以兩個常數的相對大小表達語意」本身就是這次 bug 的
成因 —— 語意要寫在語意的位置。

### 4.2 `upside_pct` 除役

`analysis.py:380-384, 403-404` 不再以它排序。它可留在個股頁面作為
「三軌合成中位數」，但強制標註「此欄位無實證預測力（見準度頁）」。
四個榜單（原 spec 7.4）改由訊號驅動。

### 4.3 目標價降級為波動區間

`_tech_prices()` 現以 LightGBM 的 q10/q50/q90 乘現價，而該分位數的
校準從未驗證 —— +41% 即由此而來。

改為：區間 ＝ 現價 × (1 ± k·σ·√(N/252))，其中 σ 為年化實現波動度
（複用 `risk.annualized_volatility`，window=60），N 為期間交易日數，
**k = 1.28**（常態假設下約對應 10/90 百分位，與原本 low/high 的語意一致）。

常態假設是明講的簡化：股價報酬有厚尾，所以實際覆蓋率會低於 80%。
這個限制必須顯示在頁面上，不得省略。

這是描述性的，回答「以此檔歷史波動，20 天內合理的價格範圍」—— 那個
問題答得出來。中位數不再宣稱方向。

**此項等於承認目前給不出有實證支撐的目標價。** 使用者原始需求中
「未來漲幅和目標價」一項，第一階段以此形式交付。

### 4.4 停用情緒軌道

`news.sentiment` 9,340 筆全為 NULL，但它在 `resolve_weights()` 中佔權重
（原 spec 6.3 設計了詞典法，未實作）。處置：先自權重移除並標「未啟用」，
**不急著接上**。情緒軌道的價值同樣應由基準率引擎裁決；接上但沒有勝率，
就是重複同一個錯誤。

## 5. 資料層

**不需要 schema migration。** 那五張表主鍵已是 `(symbol, date)` 或
`(symbol, asof)`，寫入路徑為 `INSERT OR REPLACE`（`store.py:107`）
—— 新日期新增一列，不覆寫舊列。`fundamentals` 存有 8/17 與 8/31 兩個
asof，即為追加可用的證明。

僅有 1 個日期的真正原因是**只跑過一次完整抓取**（8/31）。

故第一階段資料工作只有一件：**確保每天真的跑一次**，讓不可回補的
兩類資料（新聞、分析師）開始累積。回補工作（§1.3）屬第二階段。

## 6. 資金計算機（`src/allocate.py`）

### 6.1 界線（寫進程式的形狀）

**使用者設定規則，程式計算後果。不挑股票、不建議比例、不評價該不該買。**

### 6.2 輸入（`portfolio.toml`）

```toml
本金 = 500000
單檔上限 = 0.15        # 佔本金
最多持有檔數 = 6
分批數 = 3
每批比例 = [0.4, 0.3, 0.3]
可承受最大回撤 = 0.20   # 檢查值，非最佳化目標
保留現金 = 0.10
```

### 6.3 候選標的由使用者指定

可帶入「今天觸發 `edge` 訊號的清單」，但**若清單檔數超過使用者的
上限，程式不得代為篩選** —— 回報「N 檔超過上限 M 檔，請自行指定」。
刻意如此：挑哪幾檔就是投資決策本身。

### 6.4 每檔輸出

股數（台股整股 1000 股一單位，零股分開計；美股整股）、每批股數與成本、
手續費（台股 0.1425% × 折扣，最低 20 元；賣出證交稅 0.3%；美股依設定）、
**整股化造成的落差**（必然存在）、實際佔本金比例。

### 6.5 組合層（全為描述性歷史數字）

先合成加權權益曲線，再餵給 `risk.py` 既有函式（複用，不重寫）：
歷史波動度、歷史最大回撤並與容忍值對照（**僅回報超過／未超過，
不建議換股**）、標的間平均相關係數、產業集中度（複用 `industry.py`）。

### 6.6 強制標示

> 這些是歷史波動與回撤，不是未來的。這 3 年未發生過的情境
> （2008、2020 那類）不會出現在這些數字裡。

### 6.7 分批進場

批次觸發條件為使用者填入的參數。程式僅計算「按此規則執行，
每批買幾股、花多少、剩多少現金」。不得產生「等跌 5% 再進第二批」
這類建議。

## 7. 每日輸出與排程

### 7.1 輸出

`out/daily-YYYY-MM-DD.md` 與同內容的 `.json`。現有 `index.html` 保留，
但它不是日報 —— 1.7 MB 無法貼入外部工具。大小預算 < 50 KB，以測試守住。

### 7.2 內容順序（刻意）

1. **準度計分卡** —— 留存筆數、命中率、IC、「尚未走滿期間」警告，
   以及「上次成功抓取：YYYY-MM-DD」。放第一是因為它決定讀者該多信下面的東西。
2. 今天觸發的 `edge` 訊號：標的、訊號名、歷史勝率＋baseline 對照、
   `n_effective`、5/10/20 日
3. `no_edge` / `insufficient` 訊號，分區並標註
4. 波動區間（不稱目標價）
5. 資金算術（若存在 config）
6. 資料缺口與降級來源（沿用現有 `stats['degraded']`）

### 7.3 排程

**一個 Windows 工作排程器任務，每天 06:30（台北）。**

- 選 06:30 而非盤後：美股 16:00 ET 收盤＝台北 04:00~05:00，故 06:30
  可同時取得台股前一交易日與美股剛收盤的資料，且仍在台股 09:00 開盤前。
  晚間執行則美股永遠落後一盤。
- 每天執行，不排除假日：`INSERT OR REPLACE` 於 `(symbol, date)` 等冪，
  非交易日執行為無害空轉。把兩個市場的交易日曆編進排程器，
  複雜度換不到東西。

**失敗可見性（此項為排程的一部分，非附加功能）**：工作排程器的任務
會靜默失敗，而我們已踩過 TWSE 的 TLS 與 TPEx 的 Cloudflare
（原 spec 9.5、9.6）。抓取中斷三週而使用者不知情，等於白等三週 ——
而那正好是不可回補的那類資料。故：成功抓取時寫入 `meta` 表
`last_success`；日報標頭顯示該日期；超過 3 天於標頭亮警告。
排程器不需監控，日報自己會說。

## 8. 測試策略

### 8.1 植入訊號回收（引擎唯一的正確性證明）

合成價格資料、人工植入一個確實有優勢的訊號（觸發後必漲），
引擎必須判為 `edge`。反向：純隨機資料，引擎必須判為 `no_edge`。
**若引擎在純噪音中找到優勢，它就是壞的。**

### 8.2 前視偏誤偵測（shift 不變性）

將序列整體平移，訊號的觸發位置必須平移相同的量。使用未來資料的
訊號（如 `df.shift(-1)`）不滿足此性質，測試必須抓到。

### 8.3 `n_effective` 上界

永遠 ≤ 名目觸發次數；完全重疊的極端情形下趨近觸發過的區塊數。
以構造資料驗證。

### 8.4 Bootstrap CI 覆蓋率

已知真實效果的合成資料，多次重跑，CI 應涵蓋真值約 95%。

### 8.5 資金計算機（純算術，可驗精確值）

表格驅動：整股化邊界（本金恰差 1 元）、手續費最低 20 元、零股、
超過檔數上限時拒絕代選、回撤超標時的標示。

### 8.6 日報

產出 < 50 KB，且 JSON 可被 `json.loads` 解析。

### 8.7 NaN 守衛

新模組所有數值出口均須有 NaN 測試，一律經 `src/numeric.py`
（commit f1a63f5 的教訓：`max(0, min(100, nan))` 會把「沒有資料」
變成「滿分信心」）。

## 9. 已知限制（不可掩飾）

1. **有效樣本遠小於名目樣本。** 3 年歷史、20 日重疊窗口、102 檔高度
   相關的標的。即使某訊號名目觸發數千次，`n_effective` 可能只有數十。
   判為 `edge` 的訊號仍可能是運氣。
2. **60 次檢定。** 即使經 BH 校正，仍應以懷疑的態度看待唯一通過的訊號。
3. **3 年不含系統性崩盤。** 所有波動與回撤數字都缺少 2008、2020 那類情境。
4. **季報 3 年僅 12 點。** 基本面轉折訊號即使回補完成，樣本仍天生稀薄。
5. **新聞不可回補且帶倖存偏誤。** 事件驅動訊號可能永遠累積不到足夠樣本。
   現在就講清楚，而不是三個月後。
6. **第一階段給不出有實證支撐的目標價。** 見 §4.3。
